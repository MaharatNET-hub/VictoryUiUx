1. المقدمة (Introduction)
تتقدم شركة مهارات نت بهذا العرض التقني لتطوير منصة رقمية متكاملة تهدف إلى تحويل عمليات التوريد التقليدية إلى منظومة ذكية قائمة على التكامل بين الموردين والتجار ضمن شبكة B2B حديثة.
تعتمد المنصة على مزيج من:
•  إدارة الطلبات
•  نظام الدفع (فوري + آجل)
•  إدارة التحصيل المالي
•  أدوات التسويق والتحفيز
•  تقنيات تتبع المنتجات – RFID (اختياري)
وذلك بهدف تحقيق:
•  كفاءة تشغيلية عالية
•  تقليل الأخطاء البشرية
•  تسريع التدفقات المالية
•  تعزيز ولاء التجار وزيادة المبيعات
2. نظرة عامة على المشروع (Project Overview)
المنصة عبارة عن نظام مركزي لإدارة سلسلة التوريد يربط:
•  الموردين (Suppliers)
•  التجار (Merchants)
•  الإدارة (Admin)
•  مندوبي التحصيل (Collectors)
ضمن نظام موحد يتيح:
•  إدارة المنتجات والطلبات
•  إنشاء الفواتير
•  إدارة الائتمان (Credit System)
•  تحصيل المدفوعات
•  تحليل الأداء
ملاحظة مهمة: لا يعتمد النظام بشكل أساسي على تقنية RFID في عمليات الاستلام، بل يتم اعتماد الفواتير كمرجع رئيسي. ويدعم النظام استخدام تقنية RFID كميزة اختيارية لإدارة المخزون والجرد، دون الاعتماد عليها في عمليات الاستلام الأساسية، وذلك لضمان مرونة التشغيل وسهولة الاستخدام.

6.3 لوحة التحكم (Admin Panel)
لوحة التحكم هي واجهة مركزية تمكّن الإدارة من: إدارة المستخدمين (تجار / موردين / مندوبين)، إدارة المنتجات، إدارة الطلبات والفواتير، إدارة النظام المالي والتحصيل، إدارة التسويق (إعلانات + كوبونات)، ومراقبة الأداء والتقارير — وتعتمد على نظام صلاحيات (RBAC).
6.3.1 إدارة المستخدمين (User Management)
➤ إدارة التجار (Merchants)
الوظائف: عرض قائمة التجار، عرض تفاصيل التاجر (الاسم، السجل التجاري، العنوان، رقم الهاتف، الحالة نشط/موقوف).
الإجراءات: إضافة، قبول/رفض التسجيل، تعديل البيانات، إيقاف/تفعيل الحساب، عرض (الطلبات، الفواتير، الديون).
➤ إدارة الموردين (Suppliers)
الوظائف: عرض الموردين، بيانات المورد، المنتجات التابعة له.
الإجراءات: إضافة/تعديل/حذف، تفعيل/إيقاف، متابعة الأداء.
➤ إدارة مندوبي التحصيل (Collectors)
الوظائف: إضافة مندوب، تحديد المناطق، ربطه بتجار.
الإجراءات: توزيع مهام التحصيل، متابعة الأداء.
➤ إدارة الصلاحيات (RBAC)
الأدوار: Admin, Finance Manager, Operations, Support
التحكم: إمكانية إضافة أدوار، تحديد صلاحيات لكل دور.
6.3.2 إدارة المنتجات (Product Management)
الوظائف: عرض المنتجات، البحث والتصفية.
إضافة منتج: اسم المنتج، المورد، السعر، سعر البيع، نسبة الربح، صور، حالة المنتج.
الإجراءات: تعديل، حذف، إخفاء/إظهار، إدارة العروض.
ميزات متقدمة: تحديد خصومات، منتجات مميزة.
6.3.3 إدارة الطلبات (Order Management)
الوظائف: عرض جميع الطلبات، فلترة حسب (الحالة، التاجر، المورد).
حالات الطلب: جديد، قيد المعالجة، تم القبول، تم التسليم، ملغي.
الإجراءات: عرض التفاصيل، تعديل الحالة، إعادة إرسال إشعارات.
6.3.4 الإدارة المالية (Financial Management)
➤ إدارة الفواتير
عرض الفواتير، فلترة (مستحقة/متأخرة/مدفوعة)، تفاصيل: التاجر، المورد، المبلغ، تاريخ الاستحقاق.
➤ إدارة المدفوعات
تسجيل دفعة، ربط الدفع بالفاتورة.
➤ إدارة الشيكات
رفع صورة الشيك، أرشفة، عرض الحالة: مستلم / قيد التحصيل / محصل.
➤ إدارة الديون
عرض ديون كل تاجر، تنبيهات التأخير.
➤ التقارير المالية
إجمالي المبيعات، إجمالي التحصيل، الفواتير المتأخرة، التدفقات النقدية.
➤ إدارة الائتمان (Credit Management)
الوظائف: تحديد حد ائتماني لكل تاجر، تحديد مدة السداد.
الإجراءات: تعديل الحد، إيقاف التاجر عند تجاوز الحد.
التنبيهات: تجاوز الحد، تأخر السداد.
6.3.5 إدارة الإعلانات (Banner &amp; Ads Management)
الوظائف: إنشاء بانر جديد. البيانات: صورة، عنوان، وصف، رابط (منتج/قسم).
التحكم: تحديد تاريخ البداية والنهاية.
أنواع الإعلانات: عروض، مواسم (رمضان/عيد)، منتجات جديدة.
ميزات: ترتيب البانرات، تفعيل/إيقاف، عرض حسب نوع المستخدم (تاجر/مورد/مندوب).
6.3.6 إدارة الكوبونات (Coupons Management)
إنشاء كوبون: رمز الكوبون، نسبة الخصم، حد الاستخدام.
الشروط: حد أدنى للطلب، تاريخ انتهاء.
التقارير: عدد الاستخدام، قيمة الخصومات.
6.3.7 إدارة المحتوى (CMS)
الصفحات: من نحن، سياسة الخصوصية، الشروط.
التحكم: تعديل النصوص، تعديل اللوغو، التحكم بمعلومات الاتصال والسوشل ميديا، دعم لغتين (العربية – الإنجليزية).
6.3.8 نظام الإشعارات (Notifications)
الأنواع: إشعارات دفع، إشعارات مالية، إشعارات تسويقية.
التحكم: إرسال جماعي، إرسال مخصص.
6.3.9 إدارة التحصيل (Collection Management)
الوظائف: عرض جدول التحصيل.
توزيع المهام: تعيين مندوب، تحديد موعد.
متابعة: حالة التحصيل، صور الشيكات.
6.3.10 التقارير والتحليلات (Analytics)
تقارير التاجر: حجم الشراء، الديون.
تقارير المورد: المبيعات، الأداء.
تقارير عامة: الطلبات، الإيرادات، المنتجات الأكثر مبيعاً.
6.3.11 الأمان والسجلات (Security &amp; Logs)
الوظائف: تسجيل جميع العمليات. عرض: من قام بالتعديل، ومتى.

6.4 نظام مندوب التحصيل (Collector System)

•  متابعة حالة "تصفية العهدة" مع الإدارة المالية
•  ملخص الإنجاز اليومي (عدد الزيارات الناجحة/الفاشلة)
•  إشعارات فورية بالمهام الطارئة أو تغييرات الجدول من الإدارة
6.5 نظام المرتجعات (Returns Management System)
يتيح النظام للتاجر طلب إرجاع بضاعة إلى المورد بعد استلامها في حال وجود سبب مبرر (تلف، خطأ في الطلب، عدم تطابق المواصفات، أو غير ذلك)، من خلال فتح تذكرة إرجاع مرتبطة بالفاتورة الأصلية.
6.5.1 فتح تذكرة الإرجاع
•  تحديد الفاتورة أو الطلب المرتبط بالمرتجع
•  تحديد سبب الإرجاع
•  تصوير المنتج المرتجع ورفع الصور مباشرة من التطبيق
•  إرفاق ملاحظات إضافية عند الحاجة
6.5.2 متابعة حالة التذكرة
•  حالات التذكرة: قيد المراجعة / مقبولة / مرفوضة / تم الاسترجاع
•  إشعار فوري للمورد عند فتح التذكرة
•  إشعار التاجر عند تغيّر حالة التذكرة
6.5.3 دور المورد والإدارة
•  مراجعة تذكرة الإرجاع والموافقة أو الرفض مع بيان السبب
•  تدخل الإدارة للفصل في النزاع عند الحاجة
•  تسوية القيمة المالية للمرتجع المقبول (تعديل الفاتورة / الرصيد الائتماني)
6.5.4 التقارير
•  عدد المرتجعات لكل مورد / تاجر
•  الأسباب الأكثر تكراراً للإرجاع
•  القيمة المالية للمرتجعات
6.6 الربط مع شركات الشحن (Shipping Companies Integration)
عند طلب التاجر بضاعة من المورد، يمنح النظام المورد إمكانية اختيار طريقة توصيل الطلب: التوصيل الذاتي عبر المورد نفسه، أو التوصيل عبر شركة شحن متعاقدة مع المنصة.

6.6.1 ربط شركات الشحن (Multi-Carrier Integration)
•  ربط النظام مع شركات شحن متعددة
•  إدارة شركات الشحن المتعاقدة من لوحة التحكم (إضافة / تعديل / إيقاف)
6.6.2 اختيار طريقة التوصيل
•  عند تجهيز الطلب يختار المورد: التوصيل عبر المورد نفسه، أو التوصيل عبر شركة شحن
•  عرض تكلفة الشحن التقديرية بحسب شركة الشحن المختارة
6.6.3 التتبع والإشعارات
•  ربط رقم تتبع الشحنة (Tracking Number) بالطلب والفاتورة
•  تتبع حالة الشحنة: تم الاستلام من المورد / في الطريق / تم التسليم
•  إشعارات للتاجر والمورد عند تحديث حالة الشحنة
6.6.4 الدفع لشركات الشحن
•  تُدفع مستحقات شركة الشحن من قبل صاحب التطبيق (الإدارة) وليس من التاجر أو المورد مباشرة
•  يتم الدفع عبر بطاقة دفع إلكترونية مرتبطة بحساب الإدارة
•  عرض تقارير تكاليف الشحن ضمن الإدارة المالية

8.1 مواصفات جهاز القراءة المقترح (DS2800)
بعد مراجعة مواصفات جهاز DS2800، تبيّن أنه مناسب للفكرة بنسبة كبيرة، على أن يُعتمد كجهاز مسح باركود شبكي بديل عن قارئ RFID التقليدي المذكور في القسم السابق.
النقاط المتوافقة
•  قراءة الباركود: يدعم 1D و 2D بما فيها EAN-13, EAN-8, UPC, QR Code.
•  المسح المستمر: يدعم المسح التلقائي المستمر بدون الضغط على الزر، ويدعم منع التكرار لنفس المنتج.
•  الإرسال للسيرفر: يعمل كـ Network Device له IP خاص، ويدعم إرسال البيانات مباشرة للسيرفر عبر TCP/IP و HTTP.
•  الربط بدون PC: يمكن توصيله مباشرة على الشبكة المحلية دون الحاجة لجهاز كمبيوتر.
•  التكامل: الشركة المصنّعة توفر SDK + توثيق API + دعم لأنظمة Android، وترسل Device ID و Barcode بصيغة JSON.
•  عدة أجهزة: يدعم ربط عدة أجهزة DS2800 على نفس السيرفر في الوقت نفسه.
ملاحظات مهمة تقنية: الجهاز لا يحتوي على منفذ Ethernet RJ45، والتواصل عبر TCP/IP يتم عبر الشبكة، غالباً عن طريق WIFI؛ إذا كان الاتصال السلكي ضرورياً فيجب التنبيه على الشركة المصنّعة. كذلك يرسل الجهاز Device ID و Barcode فقط، أما وقت المسح والكمية فيجب أن يتولى تسجيلها السيرفر أو تطبيق التاجر عند استلام البيانات.

•  الخطوة القادمة: بما أن الجهاز يدعم كل المتطلبات الأساسية، يُقترح طلب جهاز عينة وملف الـ API/Protocol قبل الشراء، لاختبار الربط مع التطبيق فعلياً.

•  المسح المستمر: يدعم المسح التلقائي المستمر بدون الضغط على الزر.
•  عدد الباركود: يقرأ باركود واحد فقط في كل مرة.
•  أنواع الباركود: يدعم 1D و 2D: EAN-13, EAN-8, UPC, QR, DM, PDF417 وغيرهم.
•  المسافة: EAN-13: من 50 إلى 220 مم — QR: من 25 إلى 240 مم — DM: من 50 إلى 100 مم.
•  السرعة: في الوضع المستمر، الفاصل الافتراضي بين القراءتين 500ms ويمكن تقليله إلى 100ms؛ والحد الأقصى يعتمد على نوع الباركود والمسافة.
2. الاتصال والشبكة
•  RJ45: لا يدعم منفذ إيثرنت سلكي.
•  TCP/IP: يدعم التواصل عبر TCP/IP و HTTP.
•  IP خاص: يعمل كجهاز شبكة وله IP خاص به.
•  بدون PC: يمكن توصيله مباشرة على الشبكة المحلية دون الحاجة لجهاز كمبيوتر.
•  عدة أجهزة: يمكن ربط عدة أجهزة DS2800 على نفس السيرفر في الوقت نفسه.
•  التحكم عن بعد: يدعم التحديث والإعدادات عن طريق الشبكة.
3. التكامل مع النظام
•  الإرسال الفوري: يرسل كل باركود للسيرفر مباشرة بعد الالتقاط.
•  البيانات المرسلة: يرسل Device ID + محتوى الباركود بصيغة JSON. ملاحظة: الجهاز لا يرسل الوقت؛ الوقت والكمية يتم تسجيلهم من قبل السيرفر/التطبيق.
•  منع التكرار: يمكن ضبطه لمنع قراءة نفس المنتج مرتين وهو أمام الجهاز.
•  SDK &amp; API: توفر الشركة SDK + توثيق كامل للـ API + دعم Android.
•  بروتوكول الاتصال: يتم إرسال ملف الـ Protocol كامل قبل الشراء للتجربة.
